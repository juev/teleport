# Teleport — прокси-иконка запуска приложений и действий

Состояние: реализовано (MVP, v0.1.0). Проверено: 37 unit-тестов
(`app/src/test`), lintDebug, assembleDebug/assembleRelease, runtime-сценарии
R1–R8 и R10 на эмуляторе API 36. Не проверено runtime: R9 (перетаскивание
pinned shortcut), R11 (themed icon в лаунчере), прогон на API 26. Фаза 2
не реализована.
Источники: запрос пользователя 2026-11-13 (поведение клика и длинного клика,
настройки, расширяемость до автоматизаций); согласованные решения 2026-11-13:
scope MVP «приложения + ссылки», имя Teleport, каналы Play + F-Droid;
документация Android App Shortcuts и package visibility, Termux RUN_COMMAND
wiki, Automate Broadcast receive, Tasker Intent Received (для фазы 2).

## Назначение и границы

Teleport — Android-приложение, чья иконка на рабочем столе работает как
настраиваемая прокси-кнопка. Обычный клик запускает выбранное пользователем
приложение или открывает ссылку; длинный клик открывает меню лаунчера с
пунктом «Настройки» и списком настроенных действий.

Входит в MVP (v1): действия типов «запуск приложения» и «открытие URL /
deep link», экран настроек, синхронизация shortcuts, иконка и ассеты.

Не входит в MVP (фаза 2, модель действий закладывает расширение):
broadcast-действия (Automate, Tasker, MacroDroid), скрипты Termux,
HTTP-webhook. Не входит: виджеты, QS tiles, запуск по расписанию,
root/Shizuku, публикация в сторах и скриншоты листинга (отдельный этап).

## Требования

- R1 (клик по иконке): основное действие настроено и исполнимо → Teleport
  запускает его без собственного UI и завершает свою activity; целевое
  приложение выходит на передний план.
- R2 (первый запуск): основное действие не настроено → клик по иконке
  открывает экран настроек (онбординг).
- R3 (недоступная цель): целевое приложение удалено или ссылку некому
  открыть → Teleport не падает, открывает настройки с сообщением о
  недоступности действия.
- R4 (длинный клик): лаунчер показывает меню shortcuts: статический пункт
  «Настройки» и динамические пункты действий в пользовательском порядке.
  Пункт приложения использует иконку и название целевого приложения; пункт
  ссылки — собственную иконку и метку, заданную пользователем.
- R5 (выбор пункта): пункт действия запускает это действие по правилам
  R1–R3; пункт «Настройки» открывает экран настроек.
- R6 (настройки): пользователь выбирает основное действие; добавляет
  действия из списка всех запускаемых приложений (с поиском по названию)
  или создаёт ссылку (URI с scheme, метка по умолчанию — хост); меняет
  порядок; удаляет действия. Конфигурация сохраняется между запусками.
- R7 (синхронизация): любое изменение конфигурации пересобирает динамические
  shortcuts; удалённое действие исчезает из меню; приложение, удалённое с
  устройства, больше не предлагается как исполнимая цель.
- R8 (лимит меню): количество пунктов ограничено лимитом лаунчера
  (`getMaxShortcutCountPerActivity()`), большинство лаунчеров показывают до
  4 пунктов суммарно со статическими. В меню попадают первые действия по
  пользовательскому порядку; остальные доступны через настройки.
- R9 (pinned shortcuts): пункт меню можно вынести на рабочий стол отдельной
  иконкой штатным механизмом лаунчера; ID действий стабильны и переживают
  backup/restore и изменение конфигурации.
- R10 (приватность v1): конфигурация хранится только локально; разрешения
  не запрашиваются; видимость пакетов — `<queries>` с фильтром
  MAIN/LAUNCHER, без QUERY_ALL_PACKAGES; сетевых запросов нет.
- R11 (иконка): adaptive icon с monochrome-слоем для themed icons
  (Android 13+); ассеты стора: PNG 512×512 и feature graphic 1024×500.
- R12 (совместимость): minSdk 26, targetSdk 37. Меню длинного клика зависит
  от лаунчера: поддержка App Shortcuts и лимит пунктов различаются;
  поведение проверяется на устройстве.

## Инварианты и совместимость

- Конфигурация — единственный источник истины; shortcuts — производная
  проекция, пересобираемая из неё. Лаунчер не изменяет конфигурацию.
- ID действия стабилен от создания до удаления; смена метки, порядка или
  иконки цели ID не меняет (требование pinned shortcuts и backup/restore).
- Трамплин не оставляет Teleport поверх целевого приложения: activity
  завершается до отрисовки UI, «Назад» из целевого приложения возвращает
  на рабочий стол, а не в Teleport.
- Фаза 2 добавляет типы действий, не меняя контракт R1–R9: модель действий
  расширяется, UI настроек получает новые редакторы. Для Termux понадобятся
  `<queries>` com.termux и разрешение `com.termux.permission.RUN_COMMAND`,
  для webhook — INTERNET; это пересмотр R10 в отдельном spec-обновлении.
- F-Droid: сборка из исходников, `dependenciesInfo` исключён; релизная
  подпись через env-переменные, ключи не в репозитории (конвенция brook).
- Ограничение v1: приложения рабочего профиля могут отображаться в picker,
  но запуск через профиль не гарантирован (проверяется на устройстве;
  при необходимости фильтруются). Лаунчер без поддержки shortcuts не даёт
  доступа к настройкам после конфигурации; обход — очистка данных
  приложения (возврат к R2).

## Принятые решения

- Имя Teleport, `applicationId org.evsyukov.teleport` (конвенция
  `org.evsyukov.<имя>` как в brook). Каналы: Play + F-Droid.
- Один activity (MAIN/LAUNCHER, `singleTask`, `excludeFromRecents`). Режим
  определяется extras intent: без extras — клик по иконке (основное
  действие), extra `action_id` — shortcut действия, action
  `org.evsyukov.teleport.OPEN_SETTINGS` — настройки. Действие исполняется
  до отрисовки UI, поэтому своего UI при запуске не видно. `singleTask` и
  `onNewIntent` обязательны: лаунчер переиспользует существующую задачу
  при клике по иконке, и без них повторный клик возвращал бы в настройки
  вместо запуска (проверено на эмуляторе). Отдельный прозрачный
  activity-трамплин отклонён: лишний компонент без выигрыша.
- Модель действий: sealed-тип `AppLaunch(packageName)` и `OpenLink(uri)` с
  полями id (UUID), метка, порядок. Хранение: DataStore Preferences + JSON
  (kotlinx-serialization). Room не нужен: один небольшой список без запросов.
- Фаза 2 (проверено по документации, в MVP не реализуется):
  `Broadcast(action, extras, targetPackage?)` — Automate ловит блоком
  Broadcast receive, Tasker — событием Intent Received (только broadcast
  receiver, без явного компонента); `TermuxCommand(path, args, workdir)` —
  intent `com.termux.RUN_COMMAND`, без root, требует
  `allow-external-apps=true` в Termux; `Webhook(url, method, headers, body)`.
- Picker приложений: `PackageManager.queryIntentActivities(MAIN/LAUNCHER)`
  + `<queries>` intent-фильтр; QUERY_ALL_PACKAGES не используется
  (политика Play).
- Иконки пунктов: иконка целевого приложения через PackageManager →
  `IconCompat`; для ссылок — собственная иконка действия.
- minSdk 26: shortcuts с API 25, adaptive icons с API 26, legacy PNG-иконки
  не нужны. Стек по конвенциям brook: Kotlin, Jetpack Compose, Material3,
  version catalog, AGP 9.4.1, compileSdk/targetSdk 37, JUnit4 + Truth +
  Robolectric.
- Дизайн иконки: кольцо портала с разрывом и вылетающей стрелкой
  (градиент cyan → violet) на тёмно-индиговом фоне; monochrome-слой —
  те же формы одним цветом. Исходники и готовые ассеты — в `assets/`.

## Проверочные сценарии

- R1: настроено приложение X → клик по иконке Teleport → X на переднем
  плане, Teleport не виден. Проверка: ручной сценарий на эмуляторе +
  unit-тест резолвинга действия.
- R2: свежая установка → клик → экран настроек. Проверка: UI-тест,
  ручной сценарий.
- R3: настроено X, X удалён → клик → настройки с сообщением; ссылка без
  обработчика → то же. Проверка: unit-тест (ActivityNotFoundException) +
  ручной сценарий.
- R4/R8: настроено 6 действий, лимит лаунчера 4 → меню: «Настройки» +
  3 первых по порядку, с иконками целей. Проверка: unit-тест расчёта
  лимита + ручной на Pixel Launcher.
- R5: выбор пункта меню → запуск соответствующего действия. Проверка:
  ручной сценарий.
- R6/R7: добавление, удаление, смена порядка в настройках → меню
  обновляется без перезапуска лаунчера. Проверка: unit-тест синхронизации +
  ручной сценарий.
- R9: pinned shortcut переживает перезагрузку и обновление приложения.
  Проверка: ручной сценарий.
- R10: `aapt dump badging` не показывает разрешений; манифест без
  INTERNET. Проверка: команда + ревью манифеста.
- R11: иконка корректна в формах лаунчера (круг/squircle), themed icon на
  Android 13+. Проверка: визуальный рендер ассетов + ручной сценарий.
- R12: сборка и установка на API 26 и API 37. Проверка: эмуляторы.
